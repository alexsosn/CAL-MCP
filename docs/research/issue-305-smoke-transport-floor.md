# Issue #305 — CAL transport evidence floor for v0.1 release smoke

2026-10-11. Source-grounded offline audit of merged main e346de4; two direct CAL bibliography views made separately while researching issue #39, but **no CAL transport needed for this release-test defect**.

The only installed-wheel v0.1 release acceptance runner is `src/cal_mcp/stdio_live_smoke.py`, used by `.github/workflows/release.yml` and manually by `.github/workflows/live-smoke.yml`. Its 12 `DEFAULT_SMOKE_CASES` include exactly one deterministic local `cal_convert_to_code` and 11 **distinct** CAL-backed cases: separate lexicon noun/verb, gloss search, text search, returned text page, text concordance, bibliography lemma, dictionary collation, external citation dialects, Targum parallel verse, and Syriac Peshitta parallel verse. Each successfully exercised tool needs at least one CAL transport in a fresh installed server process; the request identities cannot all be served by one warm shared cache because each invokes different operations/selectors and the process starts without cached records. Some may consume **more than one** attempt; eleven is a conservative **lower bound, not a guarantee of upstream completion**. A 25-attempt hard cap remains.

Issue #303 established an independently reviewed v0.1 suite identity constant `_REVIEWED_V01_SMOKE_IDENTITIES`, exact case order, each `ok`, and nonzero bounded count from a private shutdown report. However `_complete_release_smoke_matrix(outcomes, actual_attempts)` still admits any `0 < actual_attempts <= 25` (including one start), and `tests/test_stdio_live_smoke_runner.py::test_stdio_cli_reports_actual_attempts` synthesizes twelve successful case outcomes and *only two starts*, explicitly treating that impossible evidence as a pass.

**Fail-open:** A monitoring bug or future operation accidentally returning successes without the required CAL I/O could pass the v0.1 publish dependency, despite not covering eleven scholarly CAL surfaces. Reject `actual_attempts < 11` for *successful full-matrix* results while preserving individual failure categories and short-circuit protective 429 behavior. The proof should derive minimum from the independently pinned identity list; never from a mutable executor matrix alone.

Non-goals: No change to CAL request pacing, case spacing, local rate cap, token-batch workflows, requested live CAL volume, publication, v0.1 frozen 36-tool surface, smoke case count or order. No successful live 37-token evidence is asserted; #262 remains open.
