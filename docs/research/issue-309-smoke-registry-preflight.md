# Issue #309 — upfront smoke registry preflight and categorical harness stop

Date: 2026-10-11. Audited exact merged-main source `32a2154ae0cafb35cbe42c8385c5bf9b6fd7e6f1`, `src/cal_mcp/stdio_live_smoke.py`, `tests/test_smoke_inter_case_schedule.py`, `tests/test_stdio_live_smoke_followup.py`, and #307's source-backed RED/GREEN.

The fixed installed-wheel v0.1 smoke matrix contains one local converter plus eleven CAL-backed cases. The smoke implementation calls `await client.list_tools()` **once** before executing the matrix, but looks up each case's `tool` in the declared registry **inside the loop**. Therefore absence of a late required tool is knowable before *any* CAL traffic, but is discovered too late, after earlier CAL-backed queries and imposed inter-case 60-second waits; the result is already a non-passing `harness` failure. Worse, the absent-tool branch appends the harness outcome then `continue`, potentially making more CAL GETs in an already doomed release smoke. A malformed test-only `from_case` follow-up whose tool is not `cal_text_page` also appends a harness failure and continues to subsequent requests.

After a successful tool invocation, terminal handling is a set of literal `harness` *message strings*. In issue #307, an omitted `"MCP output schema mismatch"` required a separate PR correction and extra CI runs. The actual contract is categorical: a `harness` result means the *MCP test invocation or schema*, not the scholarly CAL payload, is defective. No later CAL-backed call can rescue a passing release. By contrast, `drift` is intended for schema-valid but unexpected CAL content and is allowed to be aggregated across independent cases; dependent cases are safely skipped if no successful parent.

Proposed boundary: preflight *all* requested cases against the registry before making any tool call, report only the first missing required case in original declaration order as sanitized harness failure, and return immediately. For any existing harness result, terminate further calls by category rather than exact message string, retaining its specific static description. Keep ordinary scholarly drift aggregatable, direct CAL selector trust, early HTTP429/local cap, count reporting, and process-local cache.

No new CAL request, corpus fetch, scraper, package release, or change to the v0.1 public registry is justified by this offline invariant.
